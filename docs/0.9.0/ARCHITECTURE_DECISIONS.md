# Architecture decisions (consolidated Power Engine revision)

The technical background is kept in the versioned architecture and reliability records. See [ADR 0.6.1](../0.6.1/ADR_0.6.1.md) and [reliability](../0.6.1/RELIABILITY_MODEL_0.6.1.md).

- **D37 — Dynamic C# by default with a single control.** `DynamicCodePolicy` and the `bloquear_inyeccion_csharp` config. Replaces «Trusted code» (4 h) and SHA authorization in `exec`. The trust boundary is the user's pipe plus the levels; no listener is opened.
- **D38 — Rebranding of visible surfaces only.** `Protocol.Brand` concentrates the texts; technical identifiers kept the previous name. Superseded by D39.
- **D39 — Full rename to BIMBRIDGE.** `Bimbridge.*` projects, assemblies and namespaces, executables `Bimbridge.Bridge.exe` and `Bimbridge.Setup.exe`, MCP server `bimbridge` (tools `mcp__bimbridge__*`), `BIMBRIDGE_*` variables, `%APPDATA%`/`%LOCALAPPDATA%\Bimbridge` folders, `Bimbridge.*` pipes, `Bimbridge.addin` manifest (same GUID) and `Bimbridge` uninstall key. The installer migrates a previous installation with `src/Bimbridge.Setup.Core/LegacyMigration.cs`, the only file that contains the old names. Transactions with the previous prefix are no longer attributed as its own.
- **D39 — Declared identity, verified principal.** The alias is never inferred or inherited. The principal is the Windows user enforced by the ACL. Registration with `ctx agente=`, without new tools.
- **D40 — Attribution in the existing journal.** `Journal` (JSONL, background thread, bounded queue) adds agent, client, trace and document. SQLite was not added: the panel uses the in-memory ring (200) and export uses the JSONL.
- **D41 — One round trip to write.** `commit ops=…` without `plan_id` plans and applies with the same engine. Plans with geometry (job) are not merged.
- **D42 — Measurable query optimizations.** Pure count with `GetElementCount` (`QuerySpec.CanFastCount`) and a per-query cache of type, family and level names (`ElementFields.NameCache`). It lives for a single query, on the Revit thread: no invalidation needed.
- **D43 — Compact `ctx`.** The 27-capability table only appears with `detalle=true`.
- **D44 — Tests isolated from the real profile.** End-to-end tests use a temporary `BIMBRIDGE_CONFIG`.

## Consolidated delivery (branch `feat/power-engine-consolidation-0.9.0`)

- **D45 — Grant key tolerant of transient Windows locks (#21).** `GrantStore` reads `clave.bin` with `FileShare.ReadWrite | Delete` and retries, within a bounded 3 s window, only sharing violations (`HResult & 0xFFFF` equal to 32 or 33). Any other I/O error, or an access denied, ends in a `GrantKeyException` without the secret and without regenerating the key. The cross-process lock (`clave.bin.lock`) and the fail-closed rule «there are grants and there is no key» are kept. *Rejected alternative:* retrying any `IOException`, because it would hide corrupt or unreadable keys.
- **D46 — The idle threshold does not measure request duration (#1).** `PipeHost` reuses the pending read and only closes for inactivity if the session has no requests in progress (`SessionLifecycle.ShouldExpireOnIdle`). Close reason: `inactividad`. A broken connection (EOF or IOException) still closes the session immediately, and writes keep their durable intent and unknown status. *Rejected alternative:* raising the global timeout, which keeps dead sessions alive.
- **D47 — Query snapshots bound to a revision (#2).** Replaces what was rejected in D42. The first page stores the already filtered rows in `QuerySnapshotStore` and returns a `cursor`. `query cursor=… page=N` serves the following pages without entering the Revit thread. The cursor is only valid for the session that created it and for the same document (dN). If the document revision changes, it is rejected (`conflicto`) and discarded. If the revision changed during the read, no cursor is issued. Expiry: 5 min unused, 4 snapshots per session and a global budget of 1 M cells with LRU eviction. A result that does not fit falls back to classic paging. Revit API objects are never stored.
- **D48 — Supervised background jobs; CS4014 is an error (#7).** `JobStore.Run` returns `void`: the continuation observes any exception and leaves the job in a final state (`desconocido` with a reason, `cancelado` or the result). Whoever wants to wait uses `Job.Work` or `WhenFinal`. `Directory.Build.props` treats CS4014 as an error.
- **D49 — Mandatory named identity (#3; hardened by the PR #22 review).** Without an alias only `hello`, `ping` and registration (`ctx agente=…` or `ctx desregistrar=true`) are accepted. Any read (`query`, `sets`, `check`, `catalog`, `params`, `docs`, `geo`, `job`), a `ctx` without `agente=`, every write, dynamic C#, the UI, tasks and any unknown operation are rejected (`rechazado`) and recorded in the journal with their correlation. The policy lives in one place (`IdentityPolicy`, applied in `PipeHost` before dispatching). An alias in use by another active session of another process is rejected; the same bridge instance reconnecting keeps it. Config `identidad_obligatoria` (default true); in legacy mode (`false`) each anonymous operation is marked in the journal (`identidad: sin_nombre_modo_heredado`). The alias is still declared, not authentication (D39).
- **D50 — Correlation via AsyncLocal, not via arguments (#4).** `Correlation` carries agent_id (fingerprint of principal and alias), session_id, request_id, trace_id (the client's `_traza` or a new one), job_id and transaction_id (the plan id, which is the TransactionGroup name). `_traza` is removed from the arguments before dispatching and lives in `ControlArgs`, so it does not alter idempotency fingerprints.
- **D51 — session_id unique per instance (PR #22 review).** `SessionRegistry.Open` keeps the readable `S-client-pid` prefix and adds 64 random bits, and never reissues an id within one Revit run. Previously, a reconnect with the same pid reused `S-client-pid` and, since `request_id = session_id#counter` and the counter restarts, two different requests could share a request_id. The agent_id stays stable across reconnections.
- **D52 — Snapshot budget in estimated bytes (PR #22 review).** Replaces the cell limit of D47. A compact projection (only the requested columns) is stored and its managed size is estimated (dictionary, entries, UTF-16 strings, boxed values). Limits: 64 MB global, 32 MB per document, 4 snapshots per session and a 5 min TTL, with LRU eviction within the exceeded scope. A result that does not fit gets no cursor and the response says so (`cursor_no_disponible`). A cursor evicted by budget, expiry or document close answers with its reason (`Evicted`), never silently. It is an **estimate**, not a heap measurement.
- **D53 — Cross-process audit group commit (#27).** Cause confirmed in the log of run 42882010373: with 8 writers, one exhausted the 10 s wait for the `auditoria.lock` lock. Profiling showed that the line fsync costs ≈1 ms and that the lock was held ≈35–42 ms per write, mostly due to the atomic rewrite of the head (≈19 ms). With the lock free, it writes directly (same format). With the lock busy, the writer publishes its entry in `<auditoria>.pend` and waits. The leader claims all pending entries (exclusive open that deletes on close), writes them with one append, one fsync and one head, and only then answers each writer with its seq or the error. Order, seq and chain are assigned by the leader under the lock. When the 10 s expire, an unclaimed entry is withdrawn with the same primitive and fails closed. An entry claimed by a leader that crashes without confirming is not rewritten (no duplicates) and is left for reconciliation. The 10 s limit does not change. *Rejected alternatives:* raising the timeout (hides contention), in-memory queues or early acknowledgements (could acknowledge something that was not persisted) and an external service (unnecessary dependency).

## Rejected in this revision

Task DAG; scheduler with fairness; SIMD in Rust. There are no native profiles that justify them.
